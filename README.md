## Быстрый старт

### Вариант 1 — портативный EXE (рекомендуется)

1. Скачайте [**LinkAudit.exe**](https://github.com/RoBiN19666/link-audit/releases/latest) из последнего релиза.
2. Положите EXE в отдельную папку **с латинским путём**, например `C:\LinkAudit`.
3. Запустите двойным кликом.

Откроется отдельное окно **Link Audit** — без браузерных вкладок, адресной строки
и панели закладок. Внутри используется WebView2, но выглядит и ведёт себя как
обычная программа.

Первый запуск занимает 10–25 секунд. Пока сервер стартует, показывается
окно «Запускаю локальный сервер…».

Рядом с EXE появятся:

- `crawl_state.json` — прогресс обхода;
- `external_links.csv` — найденные ссылки;
- `link_status.json` — кэш HTTP-статусов;
- `crawl.log` — журнал;
- `desktop.log` — журнал запуска окна.

Чтобы остановить приложение, закройте окно программы. Чтобы обновить — замените
EXE, данные останутся.

Если нужно открыть в обычном браузере, задайте переменную
`LINK_AUDIT_BROWSER=1` перед запуском EXE.

### Вариант 2 — Python

1. Установите Python 3.10+ с [python.org](https://www.python.org/downloads/windows/).
   При установке включите **Add Python to PATH**.
2. Положите в одну папку:
   - `link_audit.py`;
   - `Запустить_аудит.bat`.
3. Дважды кликните `Запустить_аудит.bat`.

При первом запуске проверяются и при необходимости устанавливаются зависимости,
запускается Streamlit на `http://localhost:8501` и открывается браузер.

Повторный запуск при уже работающем приложении не падает: скрипт определяет
занятый порт, открывает браузер и завершается.

> После обновления файлов закройте старое окно терминала и запустите
> `Запустить_аудит.bat` заново. Если Streamlit уже работает на `8501`,
> двойной клик только откроет старую версию приложения.

### Ручной запуск

```bat
python link_audit.py
```

`streamlit run` вручную вводить не нужно.

## Кратко: подходит ли сканер под все сайты?

**Нет, не под все.** Это не универсальный браузерный робот, а аудитор
**серверного HTML** и **статических ссылок**: `<a href>`, `<area href>`,
`form action`, `button/formaction`, `data-href/url/link/target/action`,
`onclick` с `location`/`window.open`, `iframe/embed/object src` и
`meta refresh`.

Хорошо подходит для:

- WordPress: ядро `wp-sitemap.xml`, Yoast, Rank Math, AIOSEO;
- статических сайтов с `sitemap.xml`;
- корпоративных сайтов, блогов, каталогов и лендингов;
- многоязычных сайтов с `sitemapindex`;
- сайтов без sitemap, где внутренние ссылки доступны обычным обходом.

Sitemap не обязан быть полным: если на сканируемой странице есть ссылка на
внутреннюю HTML-страницу, которой нет в sitemap, она добавляется в очередь и
сканируется. Это ловит внутренние страницы, которые WordPress иногда не включает в `wp-sitemap.xml`.

Не подходит или требует доработки:

- SPA и сайты, где ссылки появляются только после JavaScript;
- закрытые сайты с авторизацией;
- сайты с обязательным обходом антибот-защиты;
- ссылки, созданные JavaScript уже после загрузки страницы;
- содержимое `<iframe>`, Shadow DOM и Canvas (сам `src` iframe собирается);
- авторизация, cookie и произвольные HTTP-заголовки.

Подробная матрица — в разделе
[«Совместимость с типами сайтов»](#совместимость-с-типами-сайтов).

## Сборка портативного EXE

Требования: Windows x64, Python 3.10+ и интернет для установки зависимостей.

```bat
build_windows.bat
```

Или вручную:

```powershell
python -m pip install -r requirements-build.txt
powershell -ExecutionPolicy Bypass -File .\build_windows.ps1
```

Готовый файл: `dist/LinkAudit.exe`. Скрипт печатает размер и SHA256.

Как это работает:

- `link_audit.py` включается в EXE как data-файл;
- Streamlit, pandas, openpyxl, pywebview и pythonnet собираются PyInstaller;
- сборка идёт в режиме `--windowed`: консольного окна нет, ошибки пишутся в
  `desktop.log`;
- при запуске EXE распаковывается во временную папку, запускает Streamlit
  внутри дочернего процесса и открывает нативное окно WebView2;
- данные (`crawl_state.json`, CSV, лог, статусы) пишутся рядом с EXE, а не во
  временную папку.

Для отладки можно задать переменные окружения `LINK_AUDIT_PORT` (порт),
`LINK_AUDIT_NO_BROWSER=1` (не открывать окно/браузер) и
`LINK_AUDIT_BROWSER=1` (открыть в обычном браузере).

GitHub Actions собирает EXE на `windows-latest`; workflow можно запустить
вручную из вкладки **Actions → Build Windows release**. Если запустить его
с тега `v*`, EXE прикрепляется к релизу.

## Интерфейс

Приложение открывается в отдельном нативном окне WebView2. Браузерные вкладки,
адресная строка и панель закладок не показываются. Тема тёмная с бирюзовым
акцентом и задаётся автоматически при старте, чтобы интерфейс выглядел
одинаково независимо от системной темы Windows.

При закрытии окна локальный Streamlit-сервер останавливается.

### Параметры

- **Стартовый URL** — по умолчанию `https://example.com`; введённое значение
  сохраняется в `crawl_state.json` и подставляется при следующем запуске.
- **Размер батча** — от 10 до 500 страниц.
- **Сканировать непрерывно** — после каждого батча автоматически запускать
  следующий, пока в очереди есть страницы. Работают пауза и экстренный тормоз.
- **Уважать robots.txt** — учитывать `Disallow` и `Sitemap`.
- **Режим скорости**:
  - **Ручной — фиксированный DELAY**;
  - **Авто — адаптация под сайт** (выбран по умолчанию).

### Кнопки

| Кнопка | Действие |
|---|---|
| `▶ Собрать sitemap` | Найти sitemap, развернуть индексы, сохранить очередь |
| `▶ Сканировать батч` | Обработать до `Размера батча` страниц; при включённом «Сканировать непрерывно» — сразу переходить к следующему батчу |
| `⏸ Пауза` | Остановиться после текущей страницы/микробатча |
| `🚨 Экстренный тормоз` | В авто-режиме поставить `DELAY = max_delay` |
| `🔄 Пересканировать страницы` | Очистить прогресс страниц и CSV, но сохранить статусы ссылок |
| `🔎 Проверить непроверенные` | Проверить статусы ещё не проверенных внешних URL |
| `♻️ Перепроверить ошибки` | Повторно проверить 4xx/5xx, SSL-предупреждения и сетевые ошибки |
| `🔁 Перепроверить все` | Проверить все уникальные внешние URL заново |
| `⏸ Пауза проверки` | Остановить проверку после текущего микробатча |
| `🗑 Сброс` | Удалить state, CSV, лог и статусы после подтверждения |

### Непрерывное сканирование

Включите **«Сканировать непрерывно»** и нажмите **«▶ Сканировать батч»** один раз.
После каждых 500 страниц приложение само запустит следующий батч, пока очередь
не опустеет. Новые внутренние страницы, найденные во время обхода, тоже
попадают в очередь и обрабатываются.

Пауза и экстренный тормоз работают как обычно: пауза завершает текущий
микробатч и останавливает цепочку.

### Пересканирование страниц

Кнопка **«🔄 Пересканировать страницы»** очищает только:

- прогресс страниц (`done`);
- найденные строки и CSV;
- статистику страниц.

Очередь sitemap и **кэш HTTP-статусов** сохраняются. Это позволяет заново
обойти сайт новым парсером (например, после добавления поддержки кнопок),
не проверяя 1455 внешних ссылок заново. После нажатия запустите
**«▶ Сканировать батч»**.

Во время повторного обхода находятся и добавляются внутренние страницы,
которых нет в sitemap.

При повторной сборке sitemap появляется подтверждение: текущий прогресс будет
сброшен.

### Прогресс

Всегда отображаются:

- общий прогресс-бар;
- `N / M (процент)`;
- скорость URL/сек;
- ETA;
- прошедшее и оставшееся время;
- последняя обработанная страница.

## Проверка статусов внешних ссылок

Проверка вынесена в отдельный блок **«🌐 Статусы внешних ссылок»**, чтобы
не замедлять обход страниц.

Как работает:

1. Из найденных строк берутся только уникальные внешние URL.
2. Выполняется `GET` с `stream=True`, тело ответа не читается.
3. Для внешних проверок используется браузерный `User-Agent`, потому что
   некоторые сайты отдают ботам `403`/`418`, хотя обычному посетителю страница
   доступна.
4. Для каждой ссылки сохраняются:
   - HTTP-код;
   - финальный URL после редиректов;
   - текст ошибки;
   - дата проверки;
   - признак проверки SSL.
5. Между запросами действует отдельная пауза (по умолчанию `0.8` сек).
6. Проверка идёт микробатчами по 20 ссылок и может быть остановлена.

Кнопки:

- **🔎 Проверить непроверенные** — только новые URL;
- **♻️ Перепроверить ошибки** — `4xx`, `5xx` и сетевые ошибки;
- **🔁 Перепроверить все** — полная повторная проверка;
- **⏸ Пауза проверки** — остановка после текущего микробатча.

Если в старом `link_status.json` уже есть `403`/`418`, в интерфейсе появится
подсказка. Нажмите **«♻️ Перепроверить ошибки»** — некоторые сайты после
этого должны стать `200`. Старый кэш автоматически не перезаписывается.

Статусы отображаются в таблице и доступны для фильтрации:

- **HTTP-статус** — точный код/ошибка/«не проверено»;
- **Показывать только проблемные** — 4xx, 5xx и сетевые ошибки.

Цветовые обозначения:

| Статус | Значение |
|---|---|
| ✅ 2xx | Успешный ответ |
| ↪️ 3xx | Редирект без перехода |
| ⚠️ 4xx | Ошибка клиента: 403, 404 и т.п. |
| ❌ 5xx | Ошибка сервера |
| 🔓 2xx/3xx | Страница доступна, но SSL-сертификат не удалось проверить |
| ⛔ Ошибка сети | Таймаут, DNS, соединение, TLS |
| — Не проверено | Проверка ещё не запускалась |

Особенности:

- проверяются только уникальные URL, без дублей;
- фрагмент `#...` не учитывается при проверке;
- используется `GET`, потому что `HEAD` часто даёт ложные `404/418/403`
  (например, сайты с антибот-защитой);
- `429/503` не долбятся повторно, а сохраняются как статус;
- `400`, `404`, `410` могут быть настоящими ошибками конкретной страницы;
- `403/418` могут означать антибот-защиту, если `GET` тоже не прошёл;
- при SSL-ошибке (неполная цепочка сертификатов, истёкший или самоподписанный
  сертификат) выполняется один повторный `GET` без проверки SSL. Страница
  получает статус `🔓 200` и предупреждение в колонке «Ошибка». Это означает
  «страница доступна, но сертификат требует внимания», а не «сайт недоступен»;
- внешние сайты получают реальные запросы, поэтому не ставьте паузу меньше
  `0.5` секунды без необходимости;
- проверка не обходит авторизацию, антибот и не выполняет JavaScript;
- `GET` может обращаться к URL с побочными действиями (например, одноразовым
  ссылкам). Не запускайте проверку на таких ссылках без понимания последствий.

Кэш статусов хранится в `link_status.json` и переживает перезапуск.

> На больших сайтах проверка может занять десятки минут: 1000 уникальных
> ссылок при паузе `0.8` сек — это около 13 минут без учёта времени ответа.
> Проверку можно ставить на паузу и продолжать позже.

## Режимы скорости

### Ручной

Фиксированная пауза между запросами:

- диапазон `0.3–10.0` секунд;
- шаг `0.1`;
- значение применяется к следующей странице;
- подходит для слабого хостинга и предсказуемой нагрузки.

### Авто

Используется AIMD-регулятор `AdaptiveThrottle`:

- начальная пауза — `1.5 сек`;
- минимум — `0.3 сек`;
- максимум — `10.0 сек`;
- окно истории — 10 ответов.

Правила:

| Событие | Действие |
|---|---|
| `429`, `503`, любой `5xx`, сетевая ошибка | после 2 ошибок подряд `delay × 2` |
| 5 успешных ответов подряд и среднее < 0.8 сек | `delay × 0.9`, но не ниже `min_delay` |
| среднее время ответа > 3 сек | `delay × 1.5`, но не выше `max_delay` |
| `🚨 Экстренный тормоз` | `delay = max_delay` |

В авто-режиме отображаются:

- **Текущий DELAY**;
- **Среднее время ответа**;
- график времени ответа по последним 10 запросам.

График появится после 3 запросов. Рост графика означает замедление сайта,
падение — что можно осторожно ускоряться.

Смена режима и слайдеров подхватывается на следующем `st.rerun()` —
обычно между микробатчами.

> При максимальной паузе 10 секунд один микробатч из 10 страниц может занимать
> до ~100 секунд. Это ожидаемое поведение защиты сайта.

## Микробатчи и пауза

Батч разбит на микробатчи по **10 страниц**:

1. Обрабатывается до 10 страниц.
2. После каждой страницы сохраняются state и CSV.
3. Обновляются прогресс и лог.
4. Выполняется `st.rerun()`.
5. Следующие 10 страниц читают уже новые настройки.

Кнопка «Пауза» останавливает обход после текущей страницы/микробатча.
Прогресс при этом уже сохранён.

Никаких фоновых потоков обхода нет: сканирование синхронное, в одном потоке
Streamlit. `threading.Thread` используется только для открытия окна или браузера
при старте приложения.

---

## Экстренный тормоз

Кнопка доступна только в авто-режиме.

Действие:

1. `throttle.delay` мгновенно становится равен `max_delay`.
2. Счётчики AIMD сбрасываются.
3. Снимок `throttle` сохраняется в state.
4. Следующий микробатч идёт с максимальной паузой.

В ручном режиме кнопка disabled. Если событие всё же пришло, оно не меняет
`manual_delay`.

## Сохранение прогресса

В `crawl_state.json` сохраняются:

- очередь URL;
- обработанные URL;
- найденные строки;
- статистика;
- параметры запуска;
- секция `throttle`.

Пример:

```json
"throttle": {
  "delay": 4.5,
  "avg_response": 0.42,
  "history": [
    [0.41, 200],
    [0.52, 200],
    [0.0, null]
  ]
}
```

`status: null` — сетевая ошибка. При следующем запуске `delay` и история
восстанавливаются, поэтому адаптация не начинается с 1.5, если сайт уже был
на грани.

Состояние пишется атомарно: временный файл + `os.replace`.

HTTP-статусы внешних ссылок хранятся отдельно — в `link_status.json`. Это
позволяет перезапускать приложение, не теряя результаты проверки, и не
раздувать `crawl_state.json`.

## Excel и CSV

Кнопка **«💾 Скачать Excel»** формирует книгу из 5 листов:

1. **Все ссылки** — страница, заголовок, анкор, URL, домен, статус, `rel`,
   `target`, контекст, финальный URL, ошибка и дата проверки; автофильтр,
   заморозка, гиперссылки.
2. **Сводка по доменам** — количество ссылок, страниц-источников, битых ссылок
   и SSL-предупреждений, топ-10 подсвечены.
3. **Проблемные**:
   - битые внешние ссылки (4xx/5xx/сеть);
   - SSL-предупреждения;
   - без анкора;
   - `nofollow`;
   - HTTP-ссылки без HTTPS.
4. **Статусы ссылок** — уникальные URL, код, финальный URL, ошибка, дата,
   число вхождений и страниц-источников.
5. **Метаданные** — даты, длительность, параметры скорости, количество ссылок,
   битых ссылок и SSL-предупреждений.

CSV скачивается отдельной кнопкой и содержит те же статусы, что и интерфейс.
Локальный `external_links.csv` остаётся «сырым» файлом обхода; объединение
со статусами выполняется при скачивании и построении отчётов.

## Совместимость с типами сайтов

### Полностью поддерживаются

| Тип сайта | Комментарий |
|---|---|
| WordPress + ядро (`wp-sitemap.xml`) | Включая дочерние sitemap-файлы |
| WordPress + Yoast / Rank Math / AIOSEO | `sitemap_index.xml`, `sitemap.xml` |
| Статические сайты (Hugo, Jekyll, Gatsby и др.) | Если есть HTML и sitemap |
| Корпоративные сайты и блоги | Sitemap или BFS-обход |
| Многоязычные сайты | `sitemapindex` и все `<loc>` |
| Сайты с публичными custom post types | Если они попали в sitemap |
| ACF-поля с кнопками | Если ссылка есть в HTML: `<a>`, `data-*` или `onclick` |

### Поддерживаются с ограничениями

| Ситуация | Ограничение |
|---|---|
| Нет sitemap | BFS по внутренним ссылкам, глубина 10, максимум 5000 страниц |
| Sitemap в `.xml.gz` | Поддерживается, включая gzip без заголовка `Content-Encoding` |
| Sitemap на нестандартном URL | Ищется через `robots.txt`; иначе BFS |
| Очень большой сайт | Лимит 200 sitemap-файлов |
| Страницы больше 5 МБ | Пропускаются |
| Медленный сайт | DELAY автоматически растёт до 10 секунд |
| `429/503` | Без внутренних ретраев; AIMD увеличивает паузу |
| Редиректы | `allow_redirects=True`, в отчёт пишется финальный URL |
| Кодировки | `r.encoding` / `apparent_encoding` |
| `<base href>` | Учитывается при разрешении относительных ссылок |
| Ссылки с `//host` | Приводятся к `https:` |
| Поддомены | Считаются внешними доменами |
| Проверка статусов внешних ссылок | GET без чтения тела, уникальные URL, SSL-предупреждения |

### Не поддерживаются

| Тип сайта / ссылок | Почему |
|---|---|
| SPA/React/Vue/Angular с JS-рендерингом | Нет headless-браузера |
| Ссылки, созданные JS после загрузки | Статические `onclick`/`data-*` разбираются, но JS не исполняется |
| Содержимое `<iframe>`, Shadow DOM, Canvas | Сам `src` iframe собирается, вложенные документы — нет |
| Закрытые сайты, Basic Auth, staging | Нет полей авторизации |
| Cloudflare/антибот с проверкой браузера | Сканер не обходит защиту |
| Бесконечная лента | Нет прокрутки и JS |
| Более 200 sitemap-файлов | Защитный лимит |
| Более 5000 страниц без sitemap | Защитный лимит BFS |
| PDF, DOC, XLS, архивы, изображения | Исключены как не-HTML |
| Проверка содержимого внешней страницы | Проверяется только HTTP-ответ |
| Мета-редиректы | Поддерживается `<meta http-equiv="refresh">`; JS-редиректы не выполняются |

### Важно про WordPress и ACF

Сканер работает **снаружи**, как обычный посетитель. Он не подключается к базе
данных WordPress и не читает ACF-поля напрямую.

Ссылка попадёт в отчёт, если:

- страница есть в sitemap или доступна по внутренним ссылкам;
- ссылка присутствует в итоговом HTML;
- это не только JS-сгенерированная ссылка: подходят `<a>`, `<area>`,
  `form action`, `button/formaction`, `data-*` и статический `onclick`.

## Ограничения по нагрузке

- Один поток, без параллельных запросов.
- Один `requests.Session` на батч обхода и один на проверку статусов.
- Пауза между запросами не меньше выбранного `DELAY`.
- При авто-режиме пауза может вырасти до `max_delay`.
- Проверка статусов идёт отдельными микробатчами с собственной паузой
  (по умолчанию `0.8` сек).
- Проверка статусов делает `GET` на внешние домены (`stream=True`), но не читает
  тело ответа и не выполняет JavaScript.
- `robots.txt` применяется к обходу страниц сайта. Для проверки статусов
  внешних URL отдельный robots.txt не загружается.
- `robots.txt` можно отключить, но делать это без разрешения владельца сайта
  не рекомендуется.
- `User-Agent` обхода сайта:
  `Mozilla/5.0 (compatible; LinkAuditBot/1.0)`.
- `User-Agent` проверки внешних ссылок — браузерный Chrome, чтобы уменьшить
  ложные `403/418` от сайтов, блокирующих ботов.

## Тестирование

Проверки, выполненные в проекте:

- компиляция `python -m py_compile link_audit.py`;

- извлечение анкоров, контекста, `rel`, `target`, `<base href>`;
- AIMD: ускорение, замедление, удвоение после 2 ошибок, max_delay;
- `snapshot()` / `restore()`;
- сохранение `throttle` в `crawl_state.json`;
- CSV: UTF-8, заголовок, лимит чтения;
- Excel: 5 листов, гиперссылки, автофильтр, кириллица, статусы, метаданные;
- микробатч на 10 страниц;
- пауза на границе микробатча;
- серия `503` и рост задержки;
- авто-пауза после 21-й ошибки;
- «Экстренный тормоз»;
- `scan_page_legacy`;
- проверка внешних ссылок: GET, 403/404/418/429, сетевые ошибки;
- сайты с ложным `418` на HEAD: GET `200`;
- сайты с ложным `404` на HEAD: GET `200`;
- SSL-fallback: сайты с неполной цепочкой → `200` с пометкой 🔓;
- Excel: сводка по SSL и раздел «SSL-предупреждения»;
- кэш `link_status.json`;
- CSV со статусами;
- UI-блок проверки статусов;
- Excel: лист «Статусы ссылок» и раздел «Битые внешние ссылки».

Тесты выполнялись на офлайн-стенде с эмуляцией HTTP-ответов и Streamlit API.
Живой прогон по конкретному сайту намеренно не выполнялся, чтобы не создавать
нагрузку на сайт.

Быстрая проверка синтаксиса:

```bat
python -m py_compile link_audit.py
```

## Диагностика

### Python не найден

Если при запуске видно:

```text
Python
Press any key to continue . . .
```

это не ошибка Link Audit. Windows нашёл только заглушку **Python** из Microsoft
Store: настоящий Python не установлен или не добавлен в PATH.

Установите Python 3.10+:

1. Откройте [python.org/downloads/windows](https://www.python.org/downloads/windows/).
2. Запустите установщик.
3. Обязательно включите **Add python.exe to PATH**.
4. Закройте старые окна терминала и снова запустите `Запустить_аудит.bat`.

`Запустить_аудит.bat` сам ищет:

- лаунчер `py`;
- `python` и `python3` в PATH;
- стандартные каталоги `%LocalAppData%\Programs\Python`,
  `C:\Program Files\Python*`, `C:\Python*`;
- Anaconda/Miniconda.

Заглушки из `WindowsApps` игнорируются. Если Python всё равно не найден,
откроется страница загрузки, а окно останется открытым с инструкцией.

Проверка в новом терминале:

```bat
py --version
```

или:

```bat
python --version
```

Должна отображаться версия **3.10 или новее**.

### Порт 8501 занят

Скрипт откроет `http://localhost:8501` и завершится. Если это не ваш Link Audit,
закройте приложение, занимающее порт.

### Не устанавливаются зависимости

Вручную:

```bat
python -m pip install requests beautifulsoup4 lxml pandas openpyxl streamlit rich tqdm
```

### Сайт отдаёт 403

Вероятно, включена антибот-защита. Сканер не обходит её. Уменьшите скорость,
проверьте правила сайта и при необходимости используйте разрешённый доступ.

### Сайт отдаёт 429/503

Авто-режим увеличит паузу. Если ошибок больше 20 подряд, батч остановится
с сообщением:

```text
Сайт не отвечает, остановите батч
```

### Excel не открывается

Закройте файл в Excel перед повторным скачиванием: Windows может блокировать
перезапись открытого файла.

### Нет графика отзывчивости

Нужно не менее 3 запросов в авто-режиме.

### Прогресс «застрял»

Проверьте `crawl.log`. При `DELAY = 10` один микробатч может идти около
100 секунд — это не зависание, а защита сайта.

### Статусы ссылок не появляются

Нажмите **«🔎 Проверить непроверенные»** в блоке
**«🌐 Статусы внешних ссылок»**. Обход страниц сам статусы внешних URL не
проверяет — это отдельная операция.

Если ссылок много, проверка идёт микробатчами по 20 штук. Следите за прогрессом.

### Много 403 или ошибок сети

Часть сайтов блокирует автоматические запросы и отдаёт `403/404/418`, хотя
браузеру страница доступна. Сканер использует браузерный `User-Agent` и `GET`,
но не обходит Cloudflare и капчу.

Если сайт открывается в браузере, но Python не может проверить TLS-цепочку,
появится статус `🔓 200` с текстом SSL-ошибки. Это предупреждение о сертификате,
а не «сайт недоступен».

### Сброс

Кнопка **«🗑 Сброс»** в интерфейсе. Альтернатива — закрыть приложение и удалить:

- `crawl_state.json`;
- `external_links.csv`;
- `link_status.json`;
- `crawl.log`.

## Безопасность и этика

- Используйте сканер только на своих сайтах или с разрешения владельца.
- Не отключайте `robots.txt` без необходимости.
- Не уменьшайте `DELAY` на слабом хостинге.
- Не запускайте несколько экземпляров против одного сайта.
- Не используйте проект для обхода авторизации или защиты.
- Проверка статусов внешних ссылок выполняется отдельно и вежливо: уникальные
  URL, `GET` без чтения тела, пауза по умолчанию `0.8` сек.
- Внешние страницы не скачиваются целиком, но запросы к чужим доменам всё же
  создают минимальную нагрузку. Не ставьте минимальную паузу без необходимости.
